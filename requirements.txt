# This file is a strict superset of vit-representation-learning's requirements.
# The two projects share one venv on the cluster, so `pip install -r` against
# this file alone must produce an environment that runs both; anything only vit
# needs is listed at the bottom under "vit-representation-learning only".
#
# Where the two disagree, this file wins, and it disagrees in exactly one place:
# vit asks for broccoli-ml and gradboard at the `neovit` *branch*, and this file
# pins them by SHA for the reason immediately below. As of 2026-08-15 those are
# the same commits -- neovit points at broccoli 33d6f21 and gradboard ae464db --
# so the superset costs vit nothing today. If they diverge later, the SHA is the
# one to keep and vit's file is the one to update.
#
# broccoli-ml and gradboard are pinned to commit SHAs, not branches. A branch
# ref is not a pin: `neovit` was used for both, and broccoli's was
# fast-forwarded onto main, taking it from 27.1.1 to 30.1.0. That added a Q/K
# RMSNorm and an output RMSNorm to every attention and feedforward block, and
# flipped the `pre_norm`/`post_norm` defaults. The result was the cluster and
# the local venv running different architectures off this same file, and
# checkpoints that cannot be resumed across the boundary (the new `out_norm`
# entries are missing keys under a strict load).
#
